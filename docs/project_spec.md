# LLM 评测系统项目定义

## 项目目标

本项目目标不是训练模型，而是证明“知道如何判断模型是否真的变好了”。项目以中文金融问答为领域，构建一个可复用的 LLM 评测框架，覆盖 golden set 构建、LLM-as-judge、多模型横向对比、训练前后 regression check 和 bad case 分类分析。

## 为什么选择中文金融问答

金融问答同时包含事实性、计算、概念解释、格式要求、风险边界和拒答能力，适合评估模型是否存在幻觉、过度承诺、投资建议越界和格式不稳定等问题。

本项目不提供真实投资建议，也不评估实时行情预测能力。涉及时效性或个性化投资建议的问题，正确行为通常是拒绝直接给结论，并提示需要基于最新信息、个人风险承受能力和专业建议判断。

## 评测对象

任何能通过 OpenAI-compatible API 调用的模型均可作为 candidate model，例如：

- base model
- SFT 后模型
- DPO 后模型
- 不同厂商闭源模型
- 本地模型通过 OpenAI-compatible server 暴露的接口

## 核心能力

1. golden set 构建：按任务类型、风险等级、拒答期望和格式要求组织样本。
2. 指标体系：准确性、忠实性、格式遵循、拒答能力、幻觉率。
3. LLM-as-judge：用强模型根据参考答案、证据和 rubric 结构化打分。
4. 多模型横向对比：同一 golden set、同一 judge prompt、同一统计脚本。
5. regression check：训练前后或版本前后自动判断是否退化。
6. bad case 分类：将失败样本归类为事实错误、证据不忠实、格式错误、拒答错误、幻觉、风险边界错误等。

## 第一版范围

第一版聚焦中文金融 QA，golden set 初始规模为 40 条左右，用于打通评测闭环。后续可以扩展到 200-500 条，并增加人工复核。

## 非目标

- 不做实时金融数据抓取。
- 不判断股票或基金未来收益。
- 不给用户个性化投资建议。
- 不将 LLM-as-judge 结果视为绝对真值；关键结果仍需要人工抽检。
